# 版本、兼容与升级

## 源码和配置

完整保留 server、web（PC/工位/TV）、Android 原生工程、simulator、installer、scripts、deploy、docs 及测试。Git 忽略凭据、数据、构建缓存与签名密钥。原型 dist/ 保留用于设计追溯，正式发布不加载它。

条码规则、SOP、产线、工位、工单、用户角色和工位授权由后台配置。首版五工序是已确认的业务路线，不允许任意绕过；未来增加路线须通过有版本的路线模型扩展，不能改写历史。

## 兼容约定

已验证兼容组合：服务器 1.0.0 对应客户端 1.0.0；服务器 1.0.1 支持工位/TV 客户端 1.0.0 和 1.0.1。客户端 1.0.1 的免登录 TV 和按长度扫码依赖新增接口，须先升级服务器到 1.0.1。通用仪器继续使用 /api/instrument/v1。服务器 /api/health 返回版本。后续 v1 只新增可选字段，不能改变已有字段语义或删除端点；破坏性变更新增 v2 并安排双版本过渡。厂家协议以独立适配器 ID 与版本注册；未知协议拒绝启用，不回退到其它厂家。

## 发布门禁

开发数据库与正式数据库完全分离。每次修改先在测试环境执行构建、迁移与重点集成回归；如需生产样本，必须使用经批准的脱敏副本。不得直接在生产数据库试改。

发布内容：Git 提交/版本标签、数据库迁移编号、服务端与客户端兼容表、安装器校验值、变更说明、验证证据和已知限制。源码仓库内不包含生产密钥。

## 升级与回退

程序目录只存可替换二进制。独立数据目录保存 PostgreSQL、SOP/附件、日志、备份、受保护配置。卸载或升级不得默认删除数据。

升级步骤：预检版本/磁盘/权限→停止应用服务以阻止写入→生成数据库和附件一致性备份→替换程序→执行 EF 迁移→启动并验证健康/附件→开放访问。不要用新版本二进制覆盖后直接忽略迁移失败。

失败时保留日志和当前状态；停止应用，恢复本次升级前的数据库和附件整套备份，恢复相同版本配置与旧程序，再验证健康后开放访问。数据库回退依靠已验证备份，不承诺任意 Down 迁移无损。恢复动作须由管理员明确确认。
