# 实际验证记录

环境：Windows x64，隔离开发目录 .local，PostgreSQL 17.11 / .NET SDK 10.0.402，API http://127.0.0.1:5080。无真实设备接入，不连接正式数据库。原始测试结果保存 .local/test-results（不包含凭据）。

## 阶段 1

`dotnet build server/Mes.Api`：通过。EF 初始迁移：已在真实 PostgreSQL 执行。

`node tests/integration/phase1.mjs`：9/9 通过：数据库+文件健康检查、匿名 401、产线五工位工单批次关系、批次超量、关联保护、工单计划安全调整、无效外键、操作员越权、退出撤销令牌。

初次退出测试因测试脚本使用 GET 失败，改为 POST 后整套复跑通过。开发 initdb 仅跳过初始化目录整体同步以绕开本机慢盘，运行时 PostgreSQL fsync 未关闭；正式安装器必须使用默认同步初始化。

浏览器插件初始化失败（运行环境禁止 node:process 导入）；最终使用本机 Playwright 驱动真实 Edge 完成 UI 验证。前端首次类型检查发现泛型空响应错误，已修复并通过重新构建。

## 阶段 2

`node tests/integration/phase2.mjs`：9/9 通过。含 12 并发同请求主码过站、10 并发同请求电芯绑定；计数均为 1。条码不合规、跳站、跨批次、未测试 SN 放行、测试工位手动扫码、历史批次删除均拦截。

前端 `npm run build --prefix web`：类型检查及 Vite 构建通过。发现 EF 设计依赖间接引用旧 Pkcs 包，已显式升级至官方公告修复版 10.0.13，再次服务端构建 0 警告/0 错误。公告：https://github.com/advisories/GHSA-846f-f764-76mx 。

## 阶段 5 与加固

`phase5.mjs`：8/8 通过。具体工单/批次范围、错配拒绝、导出含全部 PASS/FAIL/复测详细参数、TV 只读真实五工序、实际 pg_dump/SOP 备份下载、摘要预检、确认拦截、真实 pg_restore、维护中拒绝写入、恢复前备份、恢复后会话撤销、附件一致性与健康检查。

最终 `scripts/test-all.ps1`：55 项 API/真实数据库检查全部通过，Vue TypeScript/Vite 构建通过。测试脚本只允许 127.0.0.1/localhost:5080，不对生产运行。没有使用 SQLite 或内存仓库代替 PostgreSQL。
